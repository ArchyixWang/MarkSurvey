# ADR-0002：身份认证、会话与滑块挑战

- 状态：已采纳
- 日期：2026-10-20

## 背景

MarkSurvey 首个业务模块需要注册、密码与邮箱验证码登录、找回密码和租户级会话。系统尚无认证基础设施，也没有外部验证码或邮件 SaaS 凭据。

## 决策

1. 注册即创建独立租户，用户固定为 owner；本期不做邀请、成员和租户切换。
2. 账号和邮箱全局唯一、规范化小写；用户名仅作展示。
3. 密码使用 Argon2id 哈希，验证码和会话令牌只保存哈希。
4. 使用服务端会话存储和 HttpOnly Cookie，不使用 localStorage JWT；会话固定 24 小时。
5. 会话 Cookie 配合可读 CSRF Cookie 与 `X-CSRF-Token` 请求头，形成双提交校验。
6. 自建服务端拼图滑块：Pillow 生成图片，目标位置仅保存在后端，成功令牌一次性使用。
7. 邮件通过可替换 `EmailSender` 接口发送；开发环境使用日志实现，生产环境配置 SMTP。
8. MongoDB 使用 PyMongo 官方异步客户端，启动时校验连接并创建索引。

## 理由

- 服务端会话便于立即注销和密码重置后批量失效，比长期 JWT 更符合本期安全边界。
- HttpOnly Cookie 避免令牌暴露给前端脚本；CSRF 双提交为同站 Cookie 提供额外保护。
- 自建滑块不引入第三方账号和服务依赖，同时比纯前端“拖到底”具有真实服务端校验。
- Argon2id 与只保存令牌/验证码哈希可以降低数据库泄露后的直接利用风险。
- 可替换邮件实现允许本地开发完全离线联调，生产仍可接入真实 SMTP。

## 影响

- 需要维护会话、验证码、挑战和限流集合及 TTL 索引。
- 本地必须运行 MongoDB；自动化测试使用独立测试数据库。
- 自建滑块属于交互摩擦与人机基础防护，不等同于高保证反机器人服务。
- 未来增加成员或租户切换时，必须扩展用户-租户成员关系和授权模型。
- 生产部署必须设置安全密钥、SMTP 凭据和 Secure Cookie。

# ADR-0001：初始技术栈与仓库结构

- 状态：已采纳
- 日期：2026-10-20

## 背景

MarkSurvey 是一个新在线问卷系统，需要先建立可持续演进的工程基线。用户已确认前端使用 Vite、UI 遵循 Ant Design、后端使用 Python、数据库使用 MongoDB，并要求前后端与文档边界清晰。

## 决策

1. 使用单仓库组织 `frontend/`、`backend/` 和 `docs/`。
2. 前端采用 Vite + React + TypeScript + Ant Design 6。
3. 后端采用 FastAPI + Pydantic，保留清晰的应用工厂和 API 路由层。
4. MongoDB 访问将在首个持久化模块中使用 PyMongo 官方异步客户端。
5. REST API 从 `/api/v1` 起步，开发环境通过 Vite 代理联调。
6. 规格、架构、规范、变更和 AI 对话记录全部进入 `docs/`。

## 理由

- 单仓库让契约、联调、文档和小步提交保持一致，同时保留前后端独立工程边界。
- React 与 Ant Design 组合适合构建后台、表单和数据分析类界面，并有完整 Design Token 体系。
- FastAPI 的类型模型、依赖注入和 OpenAPI 能显式承载跨端契约。
- PyMongo 官方异步客户端可减少额外数据库驱动抽象，便于后续按仓储封装 MongoDB。
- 将对话与变更留档，可以让 SDD 的决策过程可追溯。

## 影响

- 前端和后端分别使用 npm 与 Python 虚拟环境，开发时需启动两个进程。
- 当前健康检查不连接 MongoDB，避免基础工程在数据库未安装时无法验证。
- 引入首个业务模块时需补充路由、全局状态、统一错误结构、数据库生命周期和测试策略。
- 技术栈升级需通过 ADR 更新，不在业务提交中静默替换。

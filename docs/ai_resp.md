### 用户原始 Prompt（实施计划）

```text
PLEASE IMPLEMENT THIS PLAN:
# MarkSurvey 多租户身份、认证与工作台一期

## Summary
- 每次注册创建一个独立租户，注册者自动成为 `owner`；本期不做邀请、成员管理、租户切换或租户设置。
- 账号与邮箱全局唯一并忽略大小写；用户名为展示昵称，可重复。密码登录接受“账号或邮箱”，验证码登录只使用邮箱。
- 注册成功后自动登录并跳转 `/workspace`；登录、找回密码完成后同样进入工作台或返回登录页。
- 工作台采用全宽顶栏 + 左侧功能栏，功能内容暂为空态；所有界面保持现有 Ant Design 主题与中文文案。

## Backend and Data
- 通过 `winget` 安装 MongoDB Community `9.0.2`，运行于本机 `27017`；新增数据库生命周期管理，启动时 ping、创建索引，关闭时释放客户端。开发环境不启用数据库认证，生产部署另行配置。
- 新建 `identity` 领域模块，内部聚合用户、租户、会话、验证码、滑块挑战和限流；路由、服务、仓储、安全工具分层。
- 集合与核心字段：
  - `tenants`：租户名称自动生成为 `{username}的工作空间`、创建时间。
  - `users`：`tenant_id`、`username`、规范化 `account`、规范化 `email`、Argon2id 密码哈希、`role=owner`、时间戳。
  - `sessions`：会话令牌哈希、用户/租户 ID、CSRF 令牌哈希、24 小时过期时间。
  - `email_codes`：邮箱、用途、HMAC 验证码、过期时间、尝试次数、消费状态。
  - `captcha_challenges`：一次性拼图目标位置、容差、尝试次数、验证令牌哈希和过期时间。
  - `rate_limits`：按动作与 IP/邮箱记录固定窗口计数。
- 建立账号、邮箱唯一索引及 TTL 索引；验证码和挑战均一次性消费。注册先建租户再建用户，用户唯一键冲突时补偿删除新租户。
- 密码规则：8–64 位且同时含字母和数字；账号 4–32 位字母、数字或下划线；用户名 2–32 字符；邮箱使用标准校验。
- 验证码为 6 位数字，10 分钟有效、60 秒重发冷却、最多验证 5 次；验证码按注册、邮箱登录、密码重置三个用途隔离。
- SMTP 通过环境变量配置；开发环境默认将验证码输出到后端日志，生产环境必须使用 SMTP。密码重置成功后注销该用户全部会话。
- 滑块挑战由后端生成 320×160 PNG 背景与拼图块，目标位置不下发给前端；容差 ±5 px、2 分钟有效、最多尝试 3 次，成功签发 5 分钟一次性 `captcha_token`。

## API and Security Contracts
- 所有接口位于 `/api/v1/auth`：
  - `POST /captcha-challenges` 与 `POST /captcha-challenges/{id}/verify`：获取并验证滑块，返回一次性验证令牌。
  - `POST /email-codes`：请求注册、邮箱登录或密码重置验证码，强制携带滑块令牌，成功返回 `202`。
  - `POST /register`：提交用户名、账号、邮箱、密码、确认密码、邮箱验证码；成功返回 `201` 并建立会话。
  - `POST /login/password`：账号或邮箱、密码、滑块令牌。
  - `POST /login/email`：邮箱与验证码；按已确认规则不再重复滑块。
  - `POST /password-reset`：邮箱、验证码、新密码、确认密码；成功返回 `204`，不自动登录。
  - `GET /session`：返回当前 `AuthSession`；未登录返回 `401`。
  - `POST /logout`：需要会话与 CSRF，删除服务端会话并清理 Cookie。
- `AuthSession` 固定为 `{ user: { id, username, account, email, role }, tenant: { id, name } }`，不返回密码、令牌或数据库内部字段。
- 会话 Cookie 为 HttpOnly、SameSite=Lax、24 小时有效，生产环境启用 Secure；另设可读 CSRF Cookie，状态变更接口要求 `X-CSRF-Token` 与 Cookie 一致。
- 统一错误结构为 `{ error: { code, message, field_errors? } }`；重复账号/邮箱返回字段错误，登录失败使用通用文案，验证码请求不暴露邮箱是否存在，限流返回 `429` 和 `Retry-After`。
- 所有业务查询必须显式携带 `tenant_id`；认证仓储负责按会话租户限定访问边界。

## Frontend and UX
- 引入 React Router DOM `7.18.4`，新增 `/login`、`/register`、`/forgot-password`、`/workspace`；`/` 根据会话跳转，未知路由回到入口，未登录访问工作台跳转登录。

- 登录页使用 Ant Design Tabs：“密码登录”提供账号或邮箱、密码与滑块；“邮箱验证码登录”先滑块后获取验证码，最终登录不再滑块。
- 注册页包含用户列出的六项信息并发送邮箱验证码；成功后自动登录。找回密码页完成邮箱验证码、新密码与确认密码后返回登录页。
- 实现可复用 `SliderCaptcha` 组件：后端图片、拖动对齐、失败自动重置、通过后向上层返回一次性令牌；验证码按钮显示 60 秒倒计时并处理 `429`。
- 表单使用 Ant Design Form 完成必填、邮箱、账号、密码强度、二次确认和验证码格式校验；服务端字段错误回填至对应输入项。

- 移除当前开发启动页的健康检查展示，保留后端健康接口；新增页面按路由懒加载。

## Validation, Delivery and Assumptions

- 文档先行提交 `docs/specs/identity-and-auth.md` 和认证 ADR，并同步更新架构、API 规范、产品概览、README、环境变量、`changelog.md` 与 `ai_resp.md`。

```

# 一、登录页规范

## 1.1 定位

- 登录页是品牌入口和认证工作区，需要兼顾品牌感、可信赖感和稳定的表单体验。
- 视觉可以比工作台更有品牌感，但不得影响登录、注册、找回密码和 OAuth 绑定流程。
- 统一使用 Ant Design 表单和反馈组件，不自绘表单体系。

## 1.2 布局

- 桌面端采用双栏布局：左侧品牌介绍区，右侧认证工作区。
- 推荐比例约 60/40，右侧认证区最小宽度约 420px。
- 页面高度使用 `100dvh`，避免移动端地址栏变化导致按钮被裁切。
- 左右区域垂直居中，认证卡片保持稳定宽度。
- 移动端降为单列：品牌摘要在上，认证卡片紧随其后。
- 登录、注册、找回密码、OAuth 补绑邮箱复用同一张认证卡片心智，不分别设计成不同页面风格。
- OAuth 首登回调使用简洁弹层，不设计成步骤向导或多层信息卡。

## 1.3 视觉

- 背景使用白色渐变，叠加低透明度蓝色和橙色径向光晕。
- 主标题使用深墨色，不使用大面积高饱和渐变文字。
- 品牌介绍区可以包含一句主标题、简短说明和能力摘要卡片。
- 认证卡片使用白色、细边框、弱阴影和轻量背景模糊。
- 品牌卡片圆角约 28px。
- 表单控件圆角约 10px。
- 登录主按钮圆角约 11px，高度不低于 38px。
- OAuth 图标按钮为圆形，尺寸约 44px。
- 橙色可用于品牌徽标、标签和少量强调，不用于替换主登录按钮的蓝色。
- 禁止使用大面积装饰插画和与认证无关的营销内容。

## 1.4 表单与交互

- 模式切换使用 Ant Design `Tabs`，不用两个普通按钮模拟 Tabs。
- 表单使用 `Form`、`Form.Item`、`Input`、`Input.Password`、`Checkbox` 和 `Button`。
- 邮箱验证码输入和发送按钮使用 `Space.Compact`。
- 字段错误优先显示在 `Form.Item` 层级。
- 顶部 `Alert` 只承载接口失败、验证码发送结果和流程说明。
- 用户协议和隐私政策使用 `Modal`，正文内部滚动。
- 登录、注册和找回密码的提交按钮必须有 loading 状态。
- 注册成功后需要明确提示 pending 用户后续进入 onboarding。
- 桌面端注册表单可以使用两列布局，移动端必须降为单列。
- 移动端邮箱输入和验证码按钮应上下排列，避免拥挤。
- 任何流程不得在 320px 宽度产生横向滚动。
- 移动端所有触控目标不小于 44px。

## 1.5 登录页禁止项

- 禁止自绘按钮、输入框、弹窗和遮罩。
- 禁止把登录、注册、找回密码做成完全不同的视觉体系。
- 禁止在认证卡片外再套多层灰色浮层。
- 禁止使用会导致布局跳动的 hover 缩放。
- 禁止在移动端把表单挤成多列。
- 禁止在 320px 宽度出现横向滚动。
- 禁止使用与品牌无关的装饰性背景图。

# 二、工作台规范

## 2.1 定位

- 工作台是面向重复性生产任务的工具型界面，优先保证稳定、清晰、高信息密度和可扫描性。
- 不使用营销式 Hero、大面积渐变、玻璃质感和装饰插画。
- 页面视觉层级通过布局、边框、字号、留白和局部语义色建立。
- 统一复用 Ant Design 和项目现有工作台组件。

## 2.2 AppShell 布局

- 顶部导航固定，桌面高度 60px，移动端 56px。
- 顶栏使用白色或半透明白色背景，配细边框和轻阴影。
- 工作台侧边栏固定，展开宽度 232px，收起宽度 72px。
- 面包屑高度约 42px。
- 页面标题栏固定高度 54px，白色背景。
- 页面标题字号约 20px，kicker 约 12px。
- 页面标题左侧放标题，右侧放操作。
- 页面标题默认不展示大段副标题，说明放入 Help、Tooltip 或空态。
- 工作台使用固定视口：导航、侧栏、面包屑、页头和筛选栏固定。
- 内容区高度通过 `100dvh` 减去顶部偏移计算。
- 表格、表单和长内容必须在内部滚动。
- 工作台核心操作不能依赖浏览器页面自然滚动。
- 侧栏被收起时，页头和内容区同步扩展，不出现空白断层。

## 2.3 页面骨架

列表页统一采用以下顺序：

1. 固定页面标题栏
2. 统计摘要，按页面需要保留
3. 单行搜索筛选栏
4. 表格或卡片主体

约束：

- 页头、摘要和筛选栏保持紧凑，不插入装饰性大标题。
- 统计摘要按需展示，不得为了凑满首屏强行增加卡片。
- 筛选栏默认保持单行。
- 超过 2–3 个低频筛选条件时，放入高级筛选 Drawer。
- 主体区域必须填满筛选栏到视口底部的剩余空间。
- 页面加载、空态和筛选变化不得造成明显位置跳动。
- 列表页优先使用表格，卡片视图只作为辅助扫描视图。

## 2.5 工作台组件

### Button

- 主操作使用蓝色 primary。
- 危险操作使用 danger。
- 低频操作使用 text 或 default。
- 图标按钮必须提供 Tooltip。
- 图标按钮尺寸约 34–40px。
- 操作区按钮高度约 34–40px。

### Form / Input / Select

- 使用 Ant Design `Form`、`Input`、`Select`、`DatePicker` 和 `InputNumber`。
- 每个字段必须有清晰 label。
- 控件高度默认 40px，圆角 8px。
- 字段错误显示在 `Form.Item` 层级。
- 筛选变化应支持防抖，避免频繁请求。
- 下拉展开不能造成页面滚动条抖动。

### Card

- 只用于指标、列表项和表单分组。
- 工作台卡片圆角不超过 8px。
- 优先使用浅边框和白底，不堆叠阴影。
- 不把每个 section 都做成浮卡。
- 指标优先做成紧凑状态条，不做大面积卡片墙。

### Tabs

- 用于同级视图切换。
- 选中态使用蓝色。
- 移动端 Tabs 可横向滚动，但不得撑出页面。
- 切换 Tabs 不应重置无关筛选条件。

### Tag

- 状态标签使用明确语义色。
- 成功绿色，警告橙色，危险红色，信息蓝色。
- 标签保持轻量，不作为页面主视觉。
- 同类状态在全站保持同一颜色。

### Drawer

- 用于详情、审核、编辑和复杂配置。
- 桌面宽度 420–720px。
- 移动端不超过视口宽度。
- 标题和底部操作固定，正文内部滚动。
- 不把复杂工作台塞入 Drawer。

### Modal

- 只用于确认、短表单和危险操作。
- 不承载复杂工作台和长流程。
- 移动端最大高度不超过视口，正文内部滚动。
- 危险操作必须说明不可逆影响。

## 2.6 表格规范

- 优先使用项目 `EnhancedTable` 或 Ant Design `Table`。
- 默认使用固定布局。
- 支持列宽拖拽和横向滚动兜底。
- 固定表格启用 sticky header。
- 表格主体内部滚动，页头、统计和筛选不随表格滚动。
- 分页固定在右下角。
- 分页启用快速跳转，按业务需要启用每页条数选择。
- 当前数据为空或少于一页时，仍保留稳定的分页区域。
- 长文本使用 `ellipsis` 或详情 Drawer。
- 长内部 ID 不作为主列，使用短编号或二级信息。
- 行操作最多保留 2–3 个高频动作，其余放入 `Dropdown`。
- 常规操作列宽度约 138px。
- 单动作操作列宽度约 92px。
- 危险操作使用 `Popconfirm` 或 `Modal.confirm`。
- 表格列宽、滚动条和操作列不得因加载或筛选发生明显抖动。

## 2.7 卡片列表

- 卡片最小宽度约 280–320px。
- 卡片结构：状态标签 → 标题和两行描述 → 3 项关键指标 → 底部标签与操作。
- 卡片视图必须复用表格的搜索、筛选、加载和空态。
- 卡片网格内部滚动，底部固定分页。
- 切换表格和卡片视图不得重置筛选语义，只重置分页。
- 卡片内容必须截断，不能因长标题撑出横向滚动。

## 2.8 反馈与加载

- 短时成功/失败提示使用顶部 `message`。
- 页面级首次加载使用 `Spin` 或 `WorkspaceLoading`。
- 表格刷新使用 `Table loading`。
- 按钮异步操作使用 `Button loading`。
- 权限不足、阻断说明和空数据使用页面内 `Alert` 或 `Empty`。
- 不使用裸文本“正在加载...”作为工作台加载态。
- 不使用自造 Toast、浮层和遮罩。
- 错误提示必须说明恢复动作。
- 自动保存状态必须可见但不干扰。
- 危险操作必须二次确认。

## 2.9 响应式与可访问性

- 桌面优先覆盖 1280px、1440px 和 1920px。
- 平板端侧边栏可收起为图标栏。
- 移动端从 320px 起必须可用。
- 任何按钮、标签和表格单元格不得出现文字溢出覆盖。
- 页面不得出现页面级横向滚动。
- 移动端触控目标不小于 44px。
- 移动端弹窗和抽屉使用 `100dvh` 约束。
- 所有图标按钮提供 Tooltip 或可访问名称。
- 保持清晰的键盘焦点态。
- 焦点环可使用 `rgba(37, 99, 235, 0.26)`。
- 动效控制在 150–300ms。
- 禁止会导致布局抖动的 hover 缩放和位移动画。

## 2.10 工作台禁止项

- 禁止使用营销式 Hero 和大面积装饰。
- 禁止使用大面积渐变和玻璃拟态。
- 禁止把所有 section 做成浮卡或卡片墙。
- 禁止自造按钮、表单、弹窗、Toast 和表格体系。
- 禁止把橙色作为全局主操作色。
- 禁止页面级纵向滚动承载核心工作台操作。
- 禁止在一个页面堆叠多组高饱和强调色。
- 禁止把长内部 ID 塞进主表格列。
- 禁止无 Tooltip 的纯图标关键操作。
- 禁止 320px 宽度出现横向滚动。

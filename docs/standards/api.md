# API 规范

状态：基础契约生效
适用范围：前后端 HTTP 接口

## 地址与版本

- 所有业务接口统一位于 `/api/v1` 下。
- 健康检查：`GET /api/v1/health`。
- 破坏性契约变化必须进入新版本路径，不在原路径静默改变语义。

## 当前基础接口

### `GET /api/v1/health`

成功响应 `200`：

```json
{
  "status": "ok",
  "service": "MarkSurvey API",
  "version": "0.1.0",
  "environment": "development"
}
```

该接口只表示 API 进程可响应，不代表 MongoDB 已连通。数据库就绪检查将在首个持久化模块中单独设计。

## 数据格式

- 请求与响应使用 JSON。
- JSON 字段统一使用 `snake_case`，前端在 feature 的 API 层直接映射，避免隐式全局转换。
- 开启或关闭凭据等安全策略由后端配置决定，前端不自行推测。
- 时间使用 UTC ISO 8601 字符串。
- 数据库中 ObjectId 对外以字符串 ID 暴露，具体字段命名在模块规格中定义。

## 响应与错误

- 使用标准 HTTP 状态码表达结果。
- 成功创建返回 `201`；无响应体删除返回 `204`；校验失败返回 `422`；未认证、无权限和资源不存在分别使用 `401`、`403`、`404`。
- 当前基础骨架保留 FastAPI 默认错误结构。首个业务模块接入前，应在对应规格中确认统一业务错误结构并同步前端处理方式。
- 服务端不得把异常堆栈、数据库错误原文或敏感配置返回客户端。

## 契约治理

- FastAPI OpenAPI 是后端接口的技术事实来源。
- 模块规格中的请求、响应示例与验收条件必须与 OpenAPI 一致。
- 跨端字段、状态或错误语义变化时，同步修改模块规格、实现、测试和 `docs/changelog.md`。
- 新增或修改接口必须完成后端测试与前端代理联调。
